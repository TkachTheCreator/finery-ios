# Finery: конвейер роликов V3 (режиссёр → исполнитель → критик → бот)

Основание: разбор роликов 20261011-002 и brag-теста от 13.10. Главные дефекты: экран телефона чёрный (нет настоящего UI), фон из одинаковых размытых пятен выглядит «нейросетевым», титры не синхронны с голосом и мелкие, анимация однотипная, зелёный кадр в конце brag-ролика не пойман QA. Правки Claude Code «из brag» (poster frame, share-copy, tone-пресеты, валидация хука) полезны, но косметические: качество картинки и звука они не меняют.

## 1. Принцип
Три роли, у каждой своя ответственность и свой вход/выход. Исполнитель не придумывает сюжет, режиссёр не рендерит, критик не чинит, а возвращает замечания.

1. **Режиссёр** (`director.py`): идея → `script.yml`. Хук с why_watch, 5–6 битов, реплика озвучки на каждый бит, звук, tone, 3 варианта хука. Выход идёт на Gate 1 (владелец в боте).
2. **Исполнитель/продюсер** (`producer`): `script.yml` → готовый ролик. Подключает «руки» (раздел 3), собирает сцены из библиотеки, озвучивает, синхронизирует титры, рендерит.
3. **Критик** (`critic`): смотрит на результат как зритель: контактный лист по секундам + аудио + титры. Проверка автоматикой (qa_check) и vision-моделью по чек-листу. Возвращает список замечаний, исполнитель правит, до 3 циклов. Только после этого ролик идёт на Gate 2 в бот. Если после 3 циклов не прошло, в бот уходит отчёт «не удалось» без видео.

## 2. Порядок работ (по одному этапу, после каждого показ владельцу)
**Этап 1. Голос и титры (audio-first).**
- Озвучка по репликам битов; из Edge TTS берутся метки слов (WordBoundary) → `captions.json` со временем каждого слова.
- Длительность сцены = длительность реплики + 0,3 с (а не наоборот). Голос стартует не раньше 0,3 с, пауза 150–250 мс между фразами, ничего не обрезается.
- Титры 2–4 слова, 64–80 px, Nunito Bold, ключевое слово золотым, в безопасной зоне, появление строго по метке слова. Тест: ролик без звука читается целиком.
- Результат этапа: ролик с уже настоящим голосом и титрами на текущей графике, в бот.

**Этап 2. Настоящий UI вместо чёрного экрана.**
- Источник экранов: запись приложения из iOS Simulator (`xcrun simctl io booted recordVideo`, статус-бар `xcrun simctl status_bar booted override --time 9:41 --batteryLevel 100 --cellularBars 4 --wifiBars 3`), демо-данные S1b, светлая тема.
- Запись кладётся в `assets/captures/<сцена>.mp4` и вставляется в корпус iPhone (PhoneRig) как видео, а не рисуется. Заголовок «Привет» кадрируется/скрывается.
- Владелец ничего не снимает, всё генерируется. Если симулятор недоступен, экраны собираются в FineryUI по макетам приложения (цвета, шрифты, данные S1b).
- Action Button: 3D-корпус iPhone в HTML/CSS (PhoneRig) с боковой кнопкой, нарисованный палец, двойное нажатие с кольцами и сжатием кнопки, затем выезд экрана быстрого ввода.
- Результат этапа: сцены с реальным приложением.

**Этап 3. Моушн и стиль.**
- Убрать одинаковые размытые пятна. Фон: плоский espresso/cream с одним смыслово связанным элементом (зерно/лёгкая виньетка, предмет сцены). Телефон 70–80 % ширины, крупные цифры, один акцентный цвет на сцену.
- Живая анимация по §10.5 `PROMPT_VIDEO_V2.md`: пружины, stagger, дуга пальца, дыхание камеры, смена скорости внутри сцены.
- Библиотека сцен (hook, device-demo, number-reveal, list-log, comparison, outro) с параметрами из `config/tones.yml`.

**Этап 4. Критик и цикл.**
- Реализовать `critic`: контактный лист 1 кадр/сек + проверка по чек-листу (хук виден в первую секунду, нет пустых/чёрных/одноцветных кадров, нет зелёного кадра, экран телефона не чёрный, титры читаются, звук совпадает с экранными событиями, CTA в конце).
- Если замечание есть, исполнитель правит и рендерит заново (до 3 раз).

## 3. «Руки» исполнителя (коннекторы)
- Edge TTS (голос `en-AU-WilliamMultilingualNeural`, SSML ru-RU) + метки слов.
- iOS Simulator (запись экрана приложения), ffmpeg, HyperFrames (локальный рендер).
- Библиотека SFX (`assets/sfx/`, Kenney CC0) и музыка (CC0, 100–120 BPM, ducking).
- HeyGen (ведущий-аватар, голос) только по явному решению владельца, сначала `heygen_check.py`.
- Telegram-бот: Gate 1 (сценарий) и Gate 2 (видео + контактный лист + share-copy).

## 4. Правила
- Ролик не уходит в бот, если критик нашёл блокирующие замечания.
- Ничего не публикуется, пока `app_store_live: false` и dry-run.
- Все дефекты, найденные владельцем, превращаются в проверку критика или правило движка (дописывается в `PROMPT_VIDEO_V2.md`).
