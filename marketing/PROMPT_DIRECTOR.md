# Задание Claude Code: агент-Режиссёр, звук и HeyGen (дополнение к архитектуре воркеров)

Прочитай docs/SMM_AGENT_BUILD.md, docs/PROMPT_VIDEO_V2.md, docs/FINERY_MOTION_STYLE.md, docs/FINERY_BRAND_BRIEF.md. Это задание ДОБАВЛЯЕТ четвёртую роль и правила, остальное остаётся в силе (очередь файлов, два шлюза одобрения, dry-run, никакого автопостинга).

## Почему
В боте пришёл тестовый сценарий из одной строки: нет хука, нет раскадровки, непонятно, что будет в видео. Владелец хочет: (1) нормальный сценарий с хуком, (2) отдельного агента-режиссёра, который передаёт сценарий производству, (3) подходящие звуки, (4) HeyGen в производстве.

## 1. Новая цепочка воркеров
Стратег (идея, тема, фича, площадки) → **Режиссёр** (полный сценарий-раскадровка) → ШЛЮЗ 1 (владелец одобряет сценарий в боте) → Продюсер (сборка видео) → ШЛЮЗ 2 (владелец одобряет видео) → Публикатор.
- Режиссёр читает `queue/ideas/`, пишет в `queue/scripts_pending/`. Стратег больше не пишет сценарий, только идею и фичу.
- Продюсер ничего не придумывает: берёт одобренный сценарий и собирает по нему. Если в сценарии чего-то не хватает, возвращает его Режиссёру (`needs_director`), а не додумывает сам.
- Общение только через файлы и `meta.json` (история статусов), как раньше.

## 2. Что выдаёт Режиссёр (формат `script.yml`)
Обязательные поля, без них сценарий не уходит в шлюз:
1. `hook` (первые 2 секунды): тип (цифра / вопрос / боль / «до-после»), текст в кадре, что видно, какой звук. Хук должен обещать то, что будет показано (пара «обещание → кадр-доказательство»).
2. `format`: moушен / iPhone-экран / ведущий HeyGen / микс; длительность 8–12 с для коротких, до 20–30 с для разборов с ведущим.
3. `beats`: 5–6 сцен (для 8–12 с), у каждой: время начала и конца, компонент движка (PhoneRig, ScreenGraph+Tap, TypeIn, CounterRoll, Callout, переходы из PROMPT_VIDEO_V2 раздел 7), какой экран из `assets/screens/`, текст в кадре (1–3 слова, точка в конце), реплика ведущего (если есть), звуки.
4. `sfx_cues`: для КАЖДОГО события (тап, переход, набор текста, счётчик, успех, вращение телефона) указан звук из `assets/sfx/` и время. Без пустых сцен: в каждой сцене минимум одно звуковое событие.
5. `music`: настроение, BPM 100–120, источник и лицензия (только royalty-free/CC0 или сгенерированное; чужие треки из CapCut/TikTok нельзя).
6. `cta` из `config/app.yml` (пока «Скоро в App Store», `app_store_live: false`).
7. `captions`: подпись и хэштеги отдельно под каждую площадку.
8. `claims_check`: Режиссёр сам помечает, что в сценарии нет обещаний дохода, гарантий экономии налога, чужих брендов, данных вне демо-аккаунта и функций с выключенным флагом в `config/features.yml`.
В бота на шлюз 1 уходит не одна строка, а карточка: хук, список сцен (по строке на сцену) и звук. Кнопки как сейчас.

## 3. Звук (обязателен, проверяется автоматически)
- Каждый ролик собирается по `sfx_cues` из сценария; микс: SFX привязаны к таймкодам, музыка прижимается на SFX, −14 LUFS, true peak −1 dB.
- QA добавляет проверки: аудиодорожка есть (ffprobe); число звуковых событий ≥ числу сцен; нет тишины длиннее 1 с; громкость в норме. Если проверка не пройдена, ролик не уходит в шлюз 2.
- Библиотека `assets/sfx/` генерируется синтезом (Python/numpy + ffmpeg) или берётся CC0; список звуков из PROMPT_VIDEO_V2 раздел 4 + «поп» плитки, «щелчок» кнопки, свуш перехода, риз перед ключевым кадром.

## 4. HeyGen
Владелец подключил HeyGen. Он даёт две разные вещи, не путай:
- **HyperFrames** (движок видео из HTML+GSAP). Локально на Mac его уже используем (`npx hyperframes render`). Облачный MCP-коннектор HyperFrames из Claude Code отключён для CLI, поэтому в фоновых воркерах работаем локальным движком.
- **ИИ-ведущий (аватар и голос)** через HeyGen API, ключ `HEYGEN_API_KEY` в `.env` (никогда не печатай и не логируй ключ).
До использования сделай короткую проверку возможностей и пришли владельцу отчёт: доступен ли ключ, какие аватары и голоса есть, поддержка русского, цена одной минуты, лимиты, как задаётся фон/прозрачность, можно ли вставить ведущего в кадр движка. Расходы считать в `meta.json["cost"]`, лимит в сутки `DAILY_BUDGET_USD`. Внешность и голос ведущего выбирает владелец: пока он не выбрал, используй один стоковый аватар только для тестов и пометь это в сценарии. Лицо реального человека без его письменного согласия не использовать.
Для ведущего Режиссёр пишет реплики 1–2 предложения, разговорные, чтобы синтез звучал естественно.

## 4a. Порядок работы
1) Сделай план на полстраницы (файлы, формат `script.yml`, что меняется в боте и QA). Жди «ок» владельца в чате. 2) Реализуй Режиссёра, карточку в боте, звуковые проверки, проверку HeyGen. 3) Прогони один настоящий сценарий через Режиссёра в шлюз 1 (не тестовую строку) и пришли владельцу. 4) Рендер ролика A по этому сценарию только после «ок» на шлюзе 1. Режим dry-run, ничего не публикуем.

## 5. Приёмка
Владелец получает в боте сценарий с хуком и раскадровкой, одобряет, затем видео со звуком. QA-сводка: длительность, звук, безопасные зоны, статус-бар, запрещённые строки, расходы. Все решения и допущения записывай в `docs/DECISIONS.md`.
