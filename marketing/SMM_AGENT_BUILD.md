# Сборка SMM-агента Finery — задание для Claude Code

Запуск (в Терминале на Mac):

    mkdir -p ~/finery-smm && cd ~/finery-smm && git init && claude --remote-control "Finery SMM"

Первое сообщение Claude Code:

    Прочитай ~/finery-ios/marketing/SMM_AGENT_BUILD.md и ~/finery-ios/marketing/FINERY_BRAND_BRIEF.md и выполни Этап 0.

---

## Цель

Построить автономного SMM-агента для приложения Finery. Он каждый день готовит ролики и подписи для Instagram, TikTok, YouTube Shorts и VK Видео и выкладывает их по расписанию **без участия владельца в момент публикации**. Владелец только одобряет материалы в Telegram-боте (одним нажатием, пачкой на неделю или по одному). Без записи об одобрении не публикуется ничего.

Весь бренд, тон, палитра, моушен, запреты на обещания и решения владельца лежат в `FINERY_BRAND_BRIEF.md`. Это источник правды. Раздел 0 брифа главнее остального. Копию положи в `docs/` нового репозитория.

## Жёсткие рамки

1. Работаешь **только** в `~/finery-smm`. Код приложения (`~/finery-ios`), боевой API и базу данных **не трогаешь**. Брифы читаешь, не правишь.
2. Секреты (токены Telegram, YouTube, VK, HeyGen, Anthropic и других) **никогда** не пишутся в код, git и чат. Они лежат только в `.env` на сервере/машине владельца, в `.gitignore`. Владелец кладёт их сам, ты даёшь `.env.example` и инструкцию. Пароли от соцсетей не запрашивай и не используй. Только официальные API и OAuth-токены.
3. Никаких обходов: не автоматизируй вход в аккаунты через браузер, не используй неофициальные API, парсинг и «серые» библиотеки для публикации. Если у площадки нет доступного официального способа, работаешь в режиме «готовый пакет в Telegram, владелец публикует вручную» (см. fallback).
4. Юридические вопросы по площадкам и рекламе решает владелец. Ты их не проверяешь и не отговариваешь, но технически публикация невозможна без одобрения.
5. Тяжёлый рендер видео не запускай на боевом сервере Finery (2 CPU, 1,9 ГБ, там идёт API). Предложи, где считается рендер (облачные API, Mac владельца, отдельный сервер), и спроси.
6. Язык бота, сообщений и подписей: русский.
7. Работай этапами. После каждого этапа: тесты зелёные, отдельные коммиты, краткий отчёт, **СТОП до моего «дальше»**.

        failed/                  ошибка публикации
      src/

        analytics/               статистика
      tests/

**Единица работы — «пакет» (папка в `queue/<статус>/<id>/`):**

    video.mp4            1080×1920, 9:16
    cover.jpg            обложка
    meta.json            {
                           "id", "created_at", "format": "iphone|cat|motion|avatar",
                           "idea", "script", "on_screen_text",
                           "captions": {"youtube": "...", "vk": "...", "tiktok": "...", "instagram": "..."},
                           "hashtags": {...},
                           "platforms": ["youtube","vk","tiktok","instagram"],
                           "scheduled_at": "2026-10-06T18:00:00+03:00",
                           "content_hash": "sha256 от video.mp4 + captions",
                           "approval": {"approved": false, "by": null, "at": null, "hash": null},
                           "cost": {"tokens": 0, "usd": 0.0}
                         }

**Правило одобрения:** одобрение привязано к `content_hash`. Если видео или подпись изменились после одобрения, одобрение сбрасывается и пакет возвращается в `pending`.

## Решения владельца на старте (5.10)

- **Сначала тестовый режим:** публикатор в `dry-run`, ничего не уходит на площадки. Владелец отсматривает пакеты в Telegram-боте. Переключение в `live` только по явной команде владельца и по площадкам по одной.
- **LLM без API-ключа:** все шаги с языковой моделью (идеи, сценарии, подписи) идут через Claude Code в headless-режиме (`claude -p`) под подпиской владельца, как в его других агентах. Один слой `llm` с единым интерфейсом, чтобы при необходимости переключить на API-ключ без переделки. `ANTHROPIC_API_KEY` не обязателен. Лимиты подписки и условия использования проверить в этапе 0.
- **Запуск локально на Mac** владельца, без сервера Timeweb. Перенос на сервер позже, отдельным этапом.
- **Управление с телефона:** Claude Code Remote Control для работы над самим агентом + Telegram-бот для одобрения контента. Mac должен быть включён и не спать (`caffeinate` или настройка энергосбережения), агент запускается через `launchd`/`tmux`, чтобы переживать закрытие терминала.

## Роли: три воркера в одном проекте (решение владельца, 5.10)

Не три отдельных самостоятельных агента, а три **независимых воркера (процесса) одного проекта**, которые общаются только через очередь на диске и состояние пакета. Так дешевле, нет рассинхрона между ними, и каждый можно отключить отдельно.

1. **Стратег (идеи):** раз в неделю строит контент-план на 7 дней по ротации фич (см. `FINERY_MOTION_STYLE.md`, раздел 9): хук, главная фича, формат (iphone/cat/motion/avatar), площадки, время. Кладёт «заявки» в `queue/ideas/`. Ничего не рендерит.
2. **Продюсер (сборка):** берёт заявку, пишет сценарий и подписи (Claude API), собирает видео через коннекторы владельца (HeyGen, Remotion/HyperFrames, ffmpeg), используя `assets/screens/`, раскадровки S1–S10 и стиль из `FINERY_MOTION_STYLE.md`. Кладёт готовый пакет в `queue/pending/` и отправляет его в Telegram-бот. Сам ничего не публикует.
3. **Публикатор:** смотрит только в `queue/approved/`, публикует по расписанию (или присылает владельцу вручную, если у площадки нет доступного API), пишет результат в `published/` или `failed/`, собирает статистику.

**Telegram-бот** — не четвёртый агент, а шлюз между Продюсером и Публикатором: только владелец (белый список ID), кнопки ✅ ❌ ✏️ 🕐. Пока нет ✅, Публикатор пакет не видит.

Дополнительная папка очереди: `queue/ideas/` (заявки Стратега) и `queue/in_production/` (Продюсер работает). Обратная связь: статистика публикаций возвращается Стратегу, и он усиливает то, что заходит.

Запуск: один процесс-планировщик (cron или systemd) запускает воркеры по расписанию, аварийный выключатель `/pause` глушит всех. Бюджет токенов и денег считается по каждому воркеру отдельно (`cost` в `meta.json`), лимит в сутки задаётся в `.env`.

## Telegram-бот (канал связи и одобрение)

- Работает **только с Telegram ID владельца** (белый список). Любой другой пользователь игнорируется.
- На пакет присылает: превью-видео, подписи по каждой площадке, расписание, результат проверки по брифу и кнопки: **✅ Одобрить**, **✏️ Правки** (владелец отвечает текстом, агент переделывает), **🕐 Другое время**, **❌ Отклонить**.
- Режим пачки: раз в неделю присылает 7 пакетов одним дайджестом и кнопку «Одобрить всё».
- Команды: `/queue` (очередь), `/today` (что выйдет сегодня), `/pause` и `/resume` (глобальная пауза, **аварийный выключатель**), `/stats`, `/help`.
- Уведомляет об ошибках публикации и о том, что запас одобренного контента заканчивается («одобренных пакетов хватит на 2 дня»).
- Автоодобрение (публикация без нажатия владельца) по умолчанию **выключено**. Можно добавить как опцию `AUTO_APPROVE=false`, но не включать.

## Публикация

- Единый интерфейс адаптера: `validate()`, `publish(package)`, `get_stats(post_id)`.
- Режимы: `dry-run` (по умолчанию, ничего не отправляет, пишет в лог), `live`.
- Планировщик берёт из `approved/` пакеты, у которых наступило время. Лимиты: не более N публикаций в сутки на площадку (настройка), окно времени (например, 10:00–22:00 МСК), пауза глушит всё.
- Адаптеры по порядку: YouTube Shorts (YouTube Data API v3, OAuth) → VK Видео (VK API, токен) → TikTok (Content Posting API) → Instagram (Graph API). **Для каждой площадки в Этапе 0 проверь, доступен ли официальный способ публикации из России для аккаунта владельца, какие нужны приложения/ревью/ограничения и сколько это занимает.** Честно напиши, где публикация автоматом невозможна или ненадёжна.
- **Fallback для площадки без доступного API:** бот присылает владельцу готовый пакет (видео, обложка, подпись) в нужное время, и он выкладывает вручную за пару кликов. Так что «без меня» тут получается только частично, скажи об этом прямо.
- Повторы при сбоях: до 3 раз с паузой, потом `failed/` и уведомление. Никаких дублей: идемпотентность по `package_id + platform`.

## Производство видео

Начинаем с дешёвого и предсказуемого. Форматы по брифу (раздел 0 и 7):

1. **iPhone с приложением внутри:** композитор накладывает запись экрана (`assets/screens/`) в нейтральную рамку iPhone, титры крупно, брендовые переходы. Записи экрана кладёт владелец, демо-аккаунт.
2. **Моушен:** шаблоны в стиле бренда (палитра, шрифт, пружины из брифа раздела 5, шиммер), крупная цифра, диаграммы. Предложи инструмент (HTML+CSS с захватом Playwright, Remotion, ffmpeg) и объясни выбор.
3. **Кот-маскот:** анимированные клипы на прозрачном фоне. Спроси владельца про способ получения ассетов, не выдумывай сам.
4. **ИИ-ведущий:** HeyGen API (ключ из `.env`), один постоянный образ. Реплики короткие, 1–2 предложения.
5. Все ролики: 9:16, 1080×1920, субтитры вшиты, первые 2 секунды с крючком, текст контрастный (не ниже 4,5:1), без чужой музыки и мемных клипов без прав.

## Статус функций (вместо автоматической проверки по брифу)

Автоматическая проверка роликов по брифу **отменена** владельцем: к запуску в приложении появятся голосовой ввод и ИИ-помощник. Контроль качества остаётся за владельцем через одобрение в боте.

Одно правило остаётся: ролик показывает только то, что есть в доступной пользователям сборке. Для этого в проекте есть файл `config/features.yml`, который владелец правит сам (или командой бота):

    released:
      quick_input_text: true
      dictation_keyboard: true
      tax_calc: true
      limit_forecast: true
      clients_invoices: true
      export: true
      widgets_lock_screen: true
      voice_input_in_app: false     # включит владелец, когда выйдет в релиз
      ai_assistant_day_parse: false # включит владелец, когда выйдет в релиз
      siri: false

Сценарист планирует ролики только про функции с `true`. Про функции с `false` готовит «тизеры без обещаний» только по прямому указанию владельца.

## Инструменты владельца (коннекторы)

У владельца подключены коннекторы для видео и анимации, в том числе **HeyGen (HyperFrames)**. Точный список владелец назовёт **[уточнить на Этапе 0]**.

- Для HeyGen HyperFrames: у размещённых в чате клиентов есть инструменты `compose` и `render_video`, а в CLI-агентах (Claude Code) они отключены. В Claude Code работай через локальные навыки HyperFrames (`npx skills add heygen-com/hyperframes`, команды вида `/hyperframes`), они делают HTML-композиции (GSAP) и рендерят их в MP4. Проверь это на Этапе 0 и скажи владельцу, как именно подключить.
- На Этапе 0 перечисли, какие инструменты видишь в окружении, и предложи, что для чего использовать (моушен, аватар, озвучка, композитинг).

## Референсы стиля анимации

Владелец присылает **примеры видео и фото приложения**. Они лежат в `assets/references/` (видео) и `assets/screens/` (фото). Что делаешь:

1. Раскадруй видео (ffmpeg, 30 кадров в секунду на ключевых переходах, остальное реже), посмотри кадры глазами.
2. Для каждого референса выпиши **спеку стиля** в `src/styles/<имя>.json`: темп монтажа (длина планов), длительность и плавность переходов (оцени кривую по положению элемента от кадра к кадру: spring, ease-out и т.д.), появление текста (по словам, по строкам, маска, масштаб), параллакс, смена сцен, ритм крупных цифр, композиция кадра, отступы, соотношение текста и пустоты.
3. **Бери только стиль**, то есть как двигается и монтируется. Не копируй чужие кадры, персонажей, ассеты, музыку, логотипы и текст.
4. Применяй спеку к **нашему бренду**: палитра и шрифт строго по брифу, пружины приложения (раздел 5 брифа) как база, стиль референса добавляет то, что в базе не описано. Если стиль референса конфликтует с брендом (например, кислотные цвета, резкие глитчи), оставь бренд и скажи об этом.
5. Покажи владельцу сравнение: кадры референса и твоя версия того же приёма в нашем стиле. Спека применяется только после «да».

## Аналитика

Раз в неделю агент собирает доступную статистику (просмотры, удержание, лайки, подписки) по площадкам, где API это позволяет, шлёт владельцу короткий отчёт в Telegram и использует выводы в следующем плане (какие форматы заходят).

## Контроль расходов

Лимит на ежедневные траты API (Anthropic, HeyGen и др.), настраиваемый в `.env`. Каждый запрос логирует токены и стоимость в `meta.json`. При превышении агент останавливается и пишет владельцу.
